| Privacy delete (cancel jobs → scrub rows → completion proof) | yes | yes | phase-one exit criterion; ordering enforced (scrub before cancel is rejected); tenant-scoped; proof carries counts only. **Now reachable**: the pipeline was previously referenced nowhere outside its own unit tests, so ADR-0005's "only an explicit privacy delete removes facts" had no way to be invoked. The documented `POST /v1/privacy/delete` and `GET /v1/privacy/delete/{id}` now ship, driven by a `DeletionService` that runs the five stages in order and marks the request **failed** — retaining the stage reached — if any raises, so a half-run deletion never reads as completed. The delete is authenticated **and** CSRF-enforced, tenant from the session (a caller can only erase their own tenant), and **synchronous**: a 200 means the data is gone, not queued. It clears the session cookie, since every session cascades away with its tenant. The status read is **unauthenticated by necessity** — the tenant and all its sessions are gone by the time a completed request is worth reading — which is safe because the id is an unguessable UUID and the response discloses only a pipeline status; unknown and cross-tenant ids are the same 404. **Two fixes in passing:** the scrub named a model list written before vitals/workouts/activity/scores/anomalies/check-ins/derivations/selections existed — all were removed by tenant cascade, but they are now deleted **explicitly**, so erasure is a property of an auditable list rather than of FK declarations spread across a dozen migrations; and `ScrubCounts` counted only the original tables, so the completion proof — the audit artifact — **under-reported** what was erased (a tenant whose only data was a check-in got `rows_scrubbed: 0`). A schema-driven regression test now walks every `tenant_id`-bearing table after a deletion and fails if any row survives, so a future table cannot silently escape the scrub |
| Tamper-evident audit events (`audit_events`) | yes | yes | migration `0026`. The security model names audit as the control for **repudiation** ("I didn't delete that"), and every `Tool` already declared an `audit` name that **nothing ever wrote** — the same declarative-only gap `requires_confirmation` had. Now `privacy.delete` appends an event on both success *and* failure (a half-run erasure is the case most worth recording). Two properties are enforced, both mutation-tested: (1) **no health values** — `metadata_json` is a bounded key/value map and any key shaped like a measurement (`hrv`, `*_score`, `sleep_min`, `steps`, …) is **rejected**, not filtered, since silently dropping a key makes an incomplete record look complete; (2) **tamper-evident** — each event hashes its own content plus the previous event's hash, so an edited, removed, or reordered row breaks every link after it, and a `GENESIS_HASH` sentinel stops a truncated chain passing as a fresh one. Append reads the tail and inserts in **one** transaction, or two writers would fork the chain. `audit_events` has **no FK to `tenants`** by design: the record must outlive the tenant it describes, or a privacy deletion would erase its own proof (real-DB tested). Honest limit: a hash chain detects row-level tampering; it does **not** defend against an attacker who can rewrite the whole chain — that needs signed batches, as the security doc's "as implementation matures" allows. Wiring beyond deletion (`connection.create`, `tool.invoke`) is not done |
| Restoration-suppression ledger | no | no | **deliberately not built**: needs a dedicated deletion key with access separation; an empty table would imply a guarantee the system cannot make |
| Backup expiry on deletion | no | no | pipeline records the stage; no backup provider is wired, so nothing is actually expired |
| Multi-tenant fact isolation | yes | yes | fact identity is tenant-scoped (migration `0010`); regression-tested after a collision bug where one tenant's fact silently overwrote another's |
| Encryption-at-rest / backup evidence | partial | partial | application-level envelope for secret columns done (see [evidence](evidence/phase-zero-envelope-encryption.md)); platform at-rest, backup/export encryption, and key separation runbooks open |
| Volume / vector spikes | no | no | Phase Zero open |
